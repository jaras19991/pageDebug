# Page Debug Snapshot 0.3.0 (2026-10-23)

Zakres: epik **E1 — Model nagrywania: dane od startu strony** (schemat paczki v2).
Licencja: MIT. Wydanie wewnętrzne — nic nie zostało wysłane do żadnego sklepu.

## Dla zgłaszającego
- Nowy przepływ w dwóch krokach: **Nagrywaj** → przeglądarka pyta o zgodę na dostęp do tej strony → strona sama się odświeża i rozszerzenie nagrywa od jej pierwszego bajtu (ikona pokazuje ●) → odtwarzasz problem → **Zapisz paczkę**.
- Błędy i zapytania, które zdarzyły się zaraz po otwarciu strony (zanim cokolwiek kliknąłeś), są teraz w paczce. Nagranie trwa też po przeładowaniach i przejściach między podstronami tej samej witryny.
- Przed „Nagrywaj” popup pokazuje listę „Do pliku trafią:” i informuje, że plik zostaje na Twoim dysku, a rozszerzenie niczego nie wysyła. Klikając „Nagrywaj”, zgadzasz się na zapisanie tych danych w pliku. Plik może zawierać Twoje dane osobowe i dane logowania — wyślij go tylko developerowi.
- Nagrywanie kończy się samo po 10 minutach; zapisać paczkę nadal można.
- „Zapisano” pojawia się dopiero, gdy plik naprawdę jest na dysku (koniec z fałszywym sukcesem przy zablokowanych pobraniach). Odmowa zgody i przerwany zapis mają czytelne komunikaty.
- Działa w Chrome i Firefoksie. W Firefoksie strony z dysku (`file://`) nie są obsługiwane — popup mówi o tym od razu.
- Po zapisie dostęp do witryny zostaje; jak go cofnąć — `README.md`. Instrukcja: `docs/INSTRUKCJA-ZGLASZAJACEGO.md`.

## Dla developera
- Schemat paczki **v2** (`schemaVersion: 2`, zmiana łamiąca względem v1): `documents[]`, `limits`, `truncated`, `source`, `recordingStartedAt`, `recordingStoppedReason`, czas `t` względem `timeOrigin`, `stack` w logach, `method`/`statusText`/`requestBody` w `network`. Opis i migracja: `docs/snapshot-schema.md`; fixture `tests/fixtures/snapshots/v2.json`.
- Przepływ jednorazowego zrzutu z E0 (`executeScript`, `window.__PAGE_DEBUG_SNAPSHOT__`) usunięty. Tło (`src/background.js`) działa jako service worker (Chrome) i event page (Firefox); stan w `storage.session`.
- Kod strony to moduły ES w `src/page`; `npm run gen` generuje z nich `src/content/{isolated,main}-world.js` i `src/standalone/console-snapshot.js` (`npm run gen -- --check` sprawdza aktualność; bundle commitujemy).
- **Wersja w dwóch miejscach:** `RECORDER_VERSION` w `src/page/constants.js` musi być równa `version` w `src/manifest.base.json` (tło odrzuca wynik zapisu przy niezgodności). Release podnosi obie i uruchamia `npm run gen` (stała jest w bundlach). Pilnuje tego test `recorder.test.js`, ale dopiero w `npm test`, nie przy `npm run pack`.
- Harness e2e: `serviceWorker()`, `stopServiceWorker()`, `grantOrigin()`, `startRecording`, `saveRecording`, `setRecordingLimit`; `PDS_E2E_NO_BUILD=1` pomija build `dist/` (równoległe przebiegi nie mogą go przebudowywać pod działającą przeglądarką).
- Testy: 618 jednostkowych, 40 e2e (Chromium); Firefox — QA ręczne (F1–F19). `npm run pack`: `dist/page-debug-snapshot-chrome-0.3.0.zip` (57 360 B) i `dist/page-debug-snapshot-firefox-0.3.0.zip` (57 458 B), po 19 plików.
- Fallback bez instalacji: `src/standalone/console-snapshot.js` (`PageDebugSnapshot.start/stop/download/snapshot`, `source: "console"`).

## Uprawnienia
- Nowe: `storage`, `downloads`; opcjonalne `optional_host_permissions`: `http://*/*`, `https://*/*`, `file:///*` — przeglądarka pyta o dostęp tylko do witryny aktywnej karty, po kliknięciu „Nagrywaj”.
- Usunięte: nic. Bez `tabs`, `webRequest`, `cookies`, `host_permissions`.
- Pozostały: `activeTab`, `scripting`. Uzasadnienia PL/EN: `README.md`.

## Znane ograniczenia
- **Dane są nadal niezredagowane** (redakcja: E3): ciasteczka, storage, nagłówki (w tym `Authorization`), treść żądań, wartości pól formularzy i `dom.html.outerHTML` trafiają do pliku wprost. Maskowane są tylko wartości pól `password` i `hidden`. Nie wysyłaj paczek osobom nieupoważnionym.
- Firefox: wpisy z własnych handlerów `beforeunload`/`pagehide` strony mogą nie trafić do paczki; strony `file://` nieobsługiwane; dodatek tymczasowy znika po restarcie; jeśli katalog pobierania jest tylko do odczytu, plik ląduje cicho w `~/Downloads`.
- W trakcie nagrywania `XMLHttpRequest.prototype.constructor === XMLHttpRequest` daje `false` (Proxy); `fetch.toString()` nie ma nazwy.
- Po uśpieniu komputera auto-stop po 10 minutach zapada dopiero przy odpaleniu timera (rekordy po terminie są odrzucane).
- Popup otwarty w trakcie przejścia karty na inną witrynę nie odświeża komunikatu `otherOrigin` (po ponownym otwarciu jest poprawny).
- Zamknięcie popupu ≤ 90 ms po „Zapisz paczkę” (Firefox) może nie dać pliku; stan „Zapisuję…” trwa do 15 s.
- Ujawnienie danych jest długie (ok. 25 linii w popupie), a okno zgody przeglądarki jest mało czytelne dla laika (UX: E2/E4). Brak `summary.md` (E4), brak kroków użytkownika (E2).
- Wpisy `documents[]` są przycinane do 100, a odpowiadające im dane w `storage.session` zostają (E3).

## Jak zainstalować 0.3.0
- Chrome: `npm ci && npm run build`, potem `chrome://extensions` → tryb dewelopera → „Załaduj rozpakowane” → `dist/chrome` (albo rozpakuj `dist/page-debug-snapshot-chrome-0.3.0.zip` i załaduj katalog).
- Firefox: `about:debugging#/runtime/this-firefox` → „Załaduj dodatek tymczasowy…” → `dist/firefox/manifest.json` (albo `npm run dev:firefox`).
- Aktualizacja z 0.2.0: usuń stare rozszerzenie, załaduj `dist/` ponownie. Nowe uprawnienia (`downloads`, `storage`) i nowy przepływ wymagają ponownego załadowania. Paczki v1 mają inną strukturę — patrz migracja w `docs/snapshot-schema.md`.

## Co dalej do publikacji
Audyt sklepowy (`docs/epics/E1/store-review.md`): dziś would-be-rejected, blokery leżą poza E1.
1. E3 — redakcja danych wrażliwych, także przed zapisem do `storage.session` (twarda bramka przed publikacją).
2. E5 — polityka prywatności pod publicznym URL i formularz „Privacy practices” (nagrywanie od przeładowania do zapisu, maks. 10 min).
3. E5 — grafiki sklepowe (small promo 440x280, zrzuty 1280x800), teksty listingu PL/EN, uzasadnienia uprawnień EN (w tym `file:///*`, notatka o `optional_host_permissions` per witryna).
4. E5 — AMO: zip źródeł + `package-lock.json` + instrukcja builda (`npm ci && npm run gen && npm run build`), bo `content/*.js` są generowane.
5. Decyzje użytkownika: kanał dystrybucji, konto wydawcy, `strict_min_version` 140 czy 128, ID Chrome z `.pem` czy nowe, ewentualne cofanie dostępu do witryny po zapisie.

## Propozycja (nie wdrożona)
Skrypt/test release'owy (np. krok `npm run pack` lub `scripts/check-release.mjs`), który po buildzie porównuje `version` w `manifest.json` obu targetów, `package.json`, `package-lock.json` i `RECORDER_VERSION` wyciągnięte z `dist/*/content/main-world.js`, żeby niezgodność wychodziła przy pakowaniu, a nie dopiero w zapisie.
